# Skill 11 · 部署与运维规范

**何时用**：部署到服务器、改端口 / 域名 / 子路径、做数据库迁移、启停服务、回滚。

**一句话原则**：部署动作必须**可重复、可回退、可交接**。AI 产出步骤与检查清单，执行和真机确认由人完成。

---

## 1. 部署前：先守再动

### 保护清单（任何情况下不覆盖）

- 生产配置：地址、端口、MQTT / 设备 IP、人设、密钥、token。
- `config_secret.json`、`.env*`、`*.key`、`*.pem`，以及各类本地化配置。
- 自有资产：`scripts/agent-sdk/`、`调试记录/`、`.learnings/` 等项目内私有目录。
- 已有数据库数据；未经确认不删表、不重置、不覆盖。

### 上线前检查

- [ ] 对照《当前方案声明》，本次改动落在当前链路上，不是废弃分支。
- [ ] 配置分层与 fail-closed 符合 `skills/08`；默认口令已替换。
- [ ] 备份已完成且验证可读（见 §2）。
- [ ] 文件清单已列出，每个文件一句话说明改了什么。
- [ ] 回滚步骤已写好（见 §7）。

---

## 2. 备份约定

- 改配置、改数据库、改服务单元**之前**先备份；备份名带时间戳，与原件分离存放。
- 数据库优先逻辑备份（如 `mysqldump`、SQLite `.backup`），尽量不停服。
- 备份要验证能读：能打开 / 能导入，而不是"文件存在"就算成功。
- 保留最近若干份可回退版本；迁移成功后也不立刻删旧备份，观察期过后再清理。

---

## 3. 部署单元约定

| 项 | 约定 |
|---|---|
| 应用进程 | systemd 托管单进程，`Restart=on-failure`，日志落到固定位置 |
| 网络 | 应用只监听 `127.0.0.1`，对外由 Nginx 反向代理暴露 |
| 子路径 | Nginx 与应用两侧同时改：代理尾斜杠、静态资源前缀、页面 base 路径要一致 |
| 环境变量 | 部署机差异走环境变量或本地配置，不进仓库（见 `skills/08`） |
| 定时任务 | crontab 用绝对路径，输出重定向到日志，避免静默失败 |
| 依赖 | 固定版本并锁定；升级依赖视为一次独立变更，不与业务改动混在一起 |

---

## 4. 数据库迁移

- 变更脚本必须**向后兼容**：可选字段禁止 NULL 覆盖，用 `COALESCE` / 默认值兜底。
- 表结构会变就设计版本号与迁移链，不靠换存储 key 补漏。
- 迁移链里存在已废弃步骤时，先对齐基线再执行升级，不要从头重放（如先标记基线，再 `upgrade head`）。
- 元数据列长度要能容纳实际迁移标识，避免因文件名过长失败。
- 先在备份库或预发环境跑一遍，再上生产。
- 迁移失败立即停：保留现场、查日志、按备份回滚，**不手工改库绕过**。

---

## 5. 人机分工（硬规则）

| 谁 | 做 | 不做 |
|---|---|---|
| AI | 产出命令清单、文件清单、验证锚点、回滚步骤；解释预期输出 | 自作主张启停服务、连生产库写入、对外发布 |
| 人 | 执行服务启停、数据库生产写入、公网操作、真机验收 | 把 AI 的"已部署成功"当成验收结论 |

- AI **不自动启动 / 重启服务**（同 `AGENTS.md` §4、`skills/07`）。
- 命令连续失败两次就停：报告现象、日志和已执行到哪一步，不连续换三种方案试。
- 任何对外渠道（推送、发消息、发版）先确认再动。

---

## 6. 上线验证

- 三层状态分开写：**静态通过 / 文档通过 / 待真机**，三者全通过才叫闭环（见 `skills/07`）。
- 每个关键功能给**日志锚点**：可 grep 的具体字符串，不能只说"试试看"。
- 端到端验收由人按清单执行；AI 不代劳、不代签。
- 灰度开关默认关闭，先确认零影响，验证后再打开。
- 部署后发现行为异常，先判断是否落在废弃链路上（`skills/10` 冲突优先级）。

---

## 7. 回滚

**触发条件**（任一即回滚）：迁移失败、服务起不来、关键功能回归、数据异常。

**顺序**：

1. 先断入口：停 Nginx 路由或定时任务，防止继续写入。
2. 恢复配置 / 数据库到备份版本，并验证可读。
3. 重启服务，按 §6 的日志锚点验证。
4. 记录原因与影响范围；不静默重来、不"再试一次就好了"。

---

## 8. 交付清单（给执行者）

一次部署要给出四样东西，缺一不可：

1. **文件清单**：路径 + 每个文件一句话说明。
2. **逐步操作**：每步命令 + 预期输出 + 失败时停在哪。
3. **验证锚点**：具体日志字符串与检查命令。
4. **回滚步骤**：触发条件与完整回退路径。

---

## 反例

- 没备份直接跑迁移，失败后无路可退。
- 可选字段用 NULL 覆盖旧数据，静默丢配置。
- AI 自述"部署成功"被当成验收结论。
- 子路径只改 Nginx，忘记改应用静态资源前缀，页面空白。
- 备份只 `ls` 看文件在，从不验证能否导入。
- 依赖升级和业务改动混在一个 commit，出问题无法定位。

## 来源与边界

- 内部：多个项目反复出现的部署约定（宝塔 / 子路径 / 端口 / systemd / Nginx / crontab / 迁移链）。
- 本规范约束**行为**，不替代具体项目的部署手册；具体路径、命令、账号写在各自项目的现场手册里。
