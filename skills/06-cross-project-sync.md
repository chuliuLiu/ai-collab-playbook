# Skill 06 · 跨项目 / 跨分支同步 SOP

**何时用**：两套代码需要对齐、跨设备同步、合并上游改动。

## 核心判据

> **文件相同 ≠ 功能一致，文件更新 ≠ 功能更全。**

三项目（xiaozhi-server / blockly-linkdog / LinkDogDM）共同踩出来的结论。

## 五步核对流程（强制）

1. MD5 + 大小 + mtime 任一不同 → 标记待查。
2. **必须拉 diff 看具体差异行，禁止只看行数**。
3. 定位差异落在哪个函数。
4. 判断该函数是否属于当前链路（查《当前方案声明》）。
5. 未逐行确认的一律标 `⚠️ 待审查`，不得默认通过。

## 五分类表

| 类别 | 含义 | 处置 |
|---|---|---|
| A-only | 仅源端有 | 评估是否引入 |
| B-only | 仅我端有 | 判断是否自有资产，保留 |
| same | 完全相同 | 跳过 |
| size_diff | 大小不同 | 拉 diff |
| content_diff | 内容不同 | 拉 diff + 函数级定位 |

## 排除项清单（固定）

`.git`、`.workbuddy`、`node_modules`、`dist`、`__pycache__`、`*.map`、`.env.production`、`*_backup.jsx`。
**自有资产**：`scripts/agent-sdk/`、`调试记录/`、`.learnings/` 等，以源为主覆盖整体源码时必须显式保留。

## 方法级比对（大 diff 专用）

面对 1800+ 行大文件的 diff：
1. 先比函数名集合差。
2. 再对同名函数块逐一 diff。
3. 结论：行数差可能只是函数顺序不同，不是功能差。

## 保护清单

- 本地化生产配置（MQTT IP、密钥、人设）**绝不覆盖**。
- 双向核对清单，不能只做单向。
- 同步后跑静态验证：`ast.parse` / `py_compile` / `node --check` + 判据函数 + 真机日志锚点。

## 反例

- 只看行数就判断"功能更全" → 幽灵代码误导（`core_backup_20260902/` 含废弃方法，搜索命中误导判断，最终整体删除 204 文件）。
