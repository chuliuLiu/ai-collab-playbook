# Skill 02 · 规格编写

**何时用**：需求已澄清，准备写代码之前。

## 步骤

1. 用 `specs/_template/spec.md` 起草稿。
2. 先写"目标"和"不做什么"——边界比功能更重要。
3. 需求只写"做什么/为什么"，不写"怎么做"。
4. 成功标准必须是可自检的判据：跑什么命令、看到什么结果。
5. 技术细节交给 plan.md，别混进 spec。

## 闸口

spec 未经人确认，不进入 plan。派出 plan 前自检：
- 有没有一句话说不清的目标？
- 有没有"弄好就行"这种无法验证的标准？
- 有没有把技术选型写进 spec（应该进 plan）？
