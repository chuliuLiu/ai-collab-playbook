# Skill 07 · 验证分层规范

**何时用**：任何改动完成后，决定"怎么验、验到什么程度算完成"。

## 三层验证

| 层 | 谁做 | 内容 | 通过标准 |
|---|---|---|---|
| 1 静态自检 | AI | 语法 / 结构 / 判据函数 | `node --check`、`py_compile`、`ast.parse`、配置数量检查、残留关键词检查 |
| 2 文档校验 | AI | diff 逐行确认、方案声明核对 | 见 Skill 06 五步流程 |
| 3 真机验收 | 用户 | 上机、日志锚点、端到端 | 用户按验收清单执行，AI 不代劳 |

## 硬规则

1. **AI 只做第 1、2 层 + 静态验证；服务启停、真机验收、跨机同步由用户执行**——这是所有项目反复确认的人机分工。
2. 无运行时环境时，用渲染探针 / 正则展开 / 纯函数单测代替，"本地仅完成 py_compile + node --check + 纯函数单测"要如实标注，不冒充真机通过。
3. 真机验收必须给日志锚点（如 `动作执行完成: self_action_group2`），不能只说"试试看"。
4. 灰度开关默认关闭（如 `enable_structured_reply` 默认 false），先关零影响，验证后再开。

## 完成定义

三层各自的状态要分开写：**静态通过 / 文档通过 / 待真机**。三者都通过才叫闭环，否则在 HANDOFF.md 里明确标"待真机验收"。
